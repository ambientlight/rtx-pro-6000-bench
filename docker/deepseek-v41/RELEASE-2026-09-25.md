# DSV4.1 preserved release — September 25, 2026

This release preserves the live L16-derived deployment, including its later
no-swap policy. Preservation does not rebuild, pause, restart or send inference
traffic to the model. It is not a checkpoint of running requests or warm KV.

Private release directory:

`/mnt/cold/dsv41_releases/release-20260925-U22fkpar`

The directory is mode 0700. It contains credentials and private inspection
records: do not publish it, add it to Git, or make it world-readable. A second
disk on this workstation is useful recovery storage, not an off-machine backup.

## Contents and boundaries

- `dsv41-image.tar`: exact image and layers, loadable with Docker. This is an
  image archive, not `docker commit` of temporary runtime files.
- `compose.restore.json`, `runtime/`, `systemd/`: frozen settings, mounted code,
  host no-swap slice, capture unit and cache-monitor unit.
- `private/`: original Compose/inspect records, thinking-signature key and a
  small `/state` backup (verification receipt, launcher state, internal API key
  and built-in startup-check results). Secrets are not in either Git commit.
- `manifest.json`: snapshot-time identity and 26 serving-source SHA-256 checks
  against the live container. Snapshot Git heads precede preservation commits.
- `release.json`, `SHA256SUMS`, `*.bundle`: final commit IDs, validation receipt,
  artifact integrity hashes and standalone Git history for both repositories
  and the pinned 0xSero recipe. `release.json` is the final source reference.
- `model-metadata/`: model configuration and weight index, not the weight shards.

Weights remain separately at
`/mnt/hot/ambientlight/models/DeepSeek-V4.1-Flash`. Captures, prior crash evidence,
warm L1/L2 state, generated compiler/kernel caches and injected host GPU drivers
are not duplicated here. Cache contents will be cold after a restore. The live
container's temporary files are not promised as a complete filesystem snapshot.
The original boot verifies/downloads the pinned Hugging Face model revision, so
a new-host restore still requires those weights and access to their upstream
metadata. CUDA/NVIDIA host-driver setup is a separate prerequisite.

## Restore procedure — manual, only during an authorized outage

Do not run `up` against an occupied GPU server just to validate this archive.
The model needs four RTX PRO 6000 GPUs, Docker with NVIDIA Container Toolkit,
systemd cgroup v2, and approximately 451.5 GiB available RAM at startup. Existing
non-model workloads can prevent the boot memory check from passing. No-swap
protection is not immunity from RAM exhaustion/OOM.

1. Keep the release directory private. Review `release.json` and run
   `sha256sum -c SHA256SUMS` from that directory.
2. Load the saved image using `docker load --input dsv41-image.tar`. The restore
   Compose pins its immutable image ID and sets `pull_policy: never`.
3. Restore the two source repositories from their Git bundles at the commits
   in `release.json`, or retain their existing checkouts. Systemd telemetry units
   reference the benchmark repository's original absolute path.
4. Ensure the pinned model weights, `/mnt/hot/dsv41_state/production` and
   `/mnt/hot/dsv41_dumps` exist with appropriate permissions. On a replacement
   host, restore the small `private/state/` backup to the state directory; do not
   overwrite a newer deployment's state. Review any changed host paths in the
   restore Compose. Its thinking key is mounted from the private archive copy.
5. Install `systemd/dsv41.slice` as `/etc/systemd/system/dsv41.slice`, then run
   `sudo systemctl daemon-reload` and `sudo systemctl enable --now dsv41.slice`.
   Confirm `/sys/fs/cgroup/dsv41.slice/memory.swap.max` is `0` before launch.
6. Create the external kernel-cache volume if absent with
   `docker volume create dsv41-sero-baseline_kernel-cache`. Its contents can
   regenerate. Confirm no other model container is occupying these GPUs.
7. Validate with `docker compose -f compose.restore.json config --quiet`, then,
   only when ready for the authorized cutover, launch with
   `docker compose -f compose.restore.json up -d --no-build deepseek`.
8. Let the normal built-in startup checks complete. Verify Docker health,
   `/health`, model alias, capture/monitor services, the parent swap limit and
   container swap usage. Install the two telemetry units as user units if
   missing; reload and enable them under the existing service account. Preserve
   that account's systemd linger setting for unattended monitoring after boot.

The snapshot utility `scripts/dsv41_snapshot_release.py` performs only read-only
deployment inspection and private artifact writes. Image saving, Git commits,
bundles, artifact checksums and final qualification are separate explicit steps.
No image push, remote Git push or production restart is part of preservation.

The historical layer builders pin their predecessor images and pre-change
source revisions; they are not a sequential rebuild recipe against the latest
HEAD. The full `Dockerfile.api` and its source allow-list include the later
host-cache diagnostics module. Prefer the archived, qualified image for exact
restoration; a new build remains a separate qualification/deployment operation.
