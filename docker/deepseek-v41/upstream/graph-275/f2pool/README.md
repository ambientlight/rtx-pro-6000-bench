# F2Pool verification with public DeepSeek requests

Four joined SGLang ranks receive a live Pearl v3 job through one authenticated F2Pool worker. The gateway uses the host's existing F2Pool mining account. The verification worker name is `joinedverify`. The GPU experiment uses a private serving port, public generated prompts and zero standalone miners, so a pool acknowledgement can be attributed to the inference experiment. [F2Pool Pearl endpoint](https://f2pool.zendesk.com/hc/en-us/articles/59741375087385-Pearl-PRL-pool-launched)

The gateway records a share as accepted when F2Pool returns a successful reply for the outstanding submission ID on its originating connection. Before submission it checks a unique match for opened weight bytes against the four pinned layer-zero checkpoint shards and runs the independently pinned Rust verifier against the corresponding F2Pool header and share target. The private gateway credential admits at most four local clients. [Protocol and receipt fields](GATEWAY.md) Arming after startup rotates their local job ID and excludes startup work. Proofs contain sampled activation and weight data. The gateway sends eligible proofs from public test inputs and keeps hashes and counters in its receipt. The F2Pool account, serving API key and raw proof are excluded from the evidence directory.

## Host run

The host wrapper expects the tested runtime and a linked checkout under `/mnt/hot/ambientlight/sglang-sm120-runtime`. Use a fresh, owner-only run directory for the gateway credential and receipts. The full-model experiment temporarily uses all four GPUs and takes the normal serving endpoint offline.

1. Start the gateway as the user unit `dsv41-f2pool-gateway` with the staged `graph-production-275/env-run` Python. Supply `--model`, `--verifier`, `--token-file`, `--arm-file` and a fresh `--receipt`. The default port is 31990. Generate a new 32-byte hexadecimal token in a mode-0600 file and leave the arm marker absent.
2. Wait for `connected: true` and a nonempty job in the gateway receipt. This establishes that the configured account received a job for the live session. Before starting SGLang, `check_transport.py --token-file PATH --gateway-receipt PATH` can verify all four client transports against its live header and target without using a GPU.
3. Start `fullmodel.py start --token-file PATH --window-minutes N` for the agreed maintenance window, including allowance for startup. It checks the incumbent's recent activity, GPU state and pinned artifacts, arms a recovery timer, and starts the checkpoint on loopback port 18002. Wait for `fullmodel.py status` to report all four native startup smokes.
4. Run `workload.py --help` for the public sampler options. Point it at port 18002, the private serving API key, the four ranks' shape files, the same arm marker and gateway receipt. Pass `--temperature-file "$RUN/serving/temperature.json"` to pause new requests at 88°C and resume at 84°C. Bound the overall request window, including cooling, with `--seconds`. Inspect the sampler's prompt and token counts, per-phase scans and the gateway's accepted-share count.
5. Run `fullmodel.py restore` to return the original service to port 8000. Verification checks the container identity, token capacity, quota, decode graph backend, four fresh native startup smokes and a public arithmetic request.

The initial F2Pool job required about 4.50 quadrillion MAC-equivalents per expected share. At the prior four-rank benchmark rate, continuous prefill would average 3.25 hours per share and continuous decode 151 hours. These are rate-based expectations. F2Pool adjusted the difficulty during the preflight session. Live estimates use the target in effect during each measured interval. Proof-worker availability and the prompt/decode mix also affect throughput.
